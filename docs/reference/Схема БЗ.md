# Схема хранения базы знаний AI-тренажёра v1

## 1. `questions`

```sql
CREATE TABLE questions (
    id              BIGSERIAL PRIMARY KEY,
    code            VARCHAR(128) NOT NULL UNIQUE,

    specialization  VARCHAR(128) NOT NULL,
    topic           VARCHAR(128) NOT NULL,

    question_text   TEXT NOT NULL,

    min_grade       SMALLINT NOT NULL
        CHECK (min_grade BETWEEN 1 AND 3),

    is_active       BOOLEAN NOT NULL DEFAULT TRUE,
    version         INTEGER NOT NULL DEFAULT 1,

    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

Грейды:

- `1` — Junior
- `2` — Middle
- `3` — Senior

Вопрос доступен кандидату, если:

```sql
target_grade >= min_grade
```

Пример:

```text
id: 42
code: attention_scaling
specialization: ml
topic: transformers
question_text: Зачем в attention делить скалярное произведение на sqrt(d_k)?
min_grade: 1
```

---

## 2. `criteria`

```sql
CREATE TABLE criteria (
    id              BIGSERIAL PRIMARY KEY,
    question_id     BIGINT NOT NULL
        REFERENCES questions(id) ON DELETE CASCADE,

    code            VARCHAR(128) NOT NULL,
    description     TEXT NOT NULL,

    sort_order      INTEGER NOT NULL DEFAULT 0,

    UNIQUE(question_id, code)
);
```

Пример:

```text
id: 101
question_id: 42
code: scaling_operation
description:
Понимает, что attention logits масштабируются делением на sqrt(d_k)
```

```text
id: 102
question_id: 42
code: scaling_reason
description:
Понимает причину масштабирования attention logits
```

Один criterion — один независимо оцениваемый аспект ответа.

---

## 3. `criterion_grade_configs`

```sql
CREATE TABLE criterion_grade_configs (
    id              BIGSERIAL PRIMARY KEY,

    criterion_id    BIGINT NOT NULL
        REFERENCES criteria(id) ON DELETE CASCADE,

    grade           SMALLINT NOT NULL
        CHECK (grade BETWEEN 1 AND 3),

    weight          NUMERIC NOT NULL
        CHECK (weight > 0),

    UNIQUE(criterion_id, grade)
);
```

Если строки для сочетания `criterion + grade` нет, этот criterion для данного грейда не используется.

Пример:

```text
criterion_id | grade  | weight
-------------|--------|-------
101          | junior | 3
102          | junior | 1

101          | middle | 3
102          | middle | 2
103          | middle | 1
```

Если criterion `103` отсутствует для Junior, он не участвует ни в оценке, ни в нормализации весов Junior.

---

## 4. `criterion_grade_anchors`

```sql
CREATE TABLE criterion_grade_anchors (
    id                          BIGSERIAL PRIMARY KEY,

    criterion_grade_config_id   BIGINT NOT NULL
        REFERENCES criterion_grade_configs(id) ON DELETE CASCADE,

    score                       SMALLINT NOT NULL
        CHECK (score >= 0),

    description                 TEXT NOT NULL,

    UNIQUE(criterion_grade_config_id, score)
);
```

Шкала может быть разной для разных criteria.

Пример бинарного criterion:

```text
score 0:
Критерий не выполнен.

score 1:
Критерий выполнен.
```

Пример criterion со шкалой `0..3`:

```text
score 0:
Причина масштабирования не раскрыта или объяснена неверно.

score 1:
Кандидат знает, что scaling нужен для стабильности,
но не объясняет связь с размерностью.

score 2:
Связывает рост величины dot product с d_k,
но объясняет неполно.

score 3:
Корректно объясняет рост дисперсии dot product с d_k
и влияние больших logits на softmax.
```

Для каждого используемого `criterion_grade_config` должен существовать:

- anchor со `score = 0`;
- хотя бы один anchor со `score > 0`.

Evaluator может вернуть только `score`, явно заданный в anchors.

## 5. `question_grade_configs`

```sql
CREATE TABLE question_grade_configs (
    id                  BIGSERIAL PRIMARY KEY,

    question_id         BIGINT NOT NULL
        REFERENCES questions(id) ON DELETE CASCADE,

    grade               SMALLINT NOT NULL
        CHECK (grade BETWEEN 1 AND 3),

    reference_answer    TEXT NOT NULL,

    UNIQUE(question_id, grade)
);
```

Пример Junior:

```text
question_id = 42
grade = 1
reference_answer =
"При вычислении attention скалярные произведения query и key
масштабируются делением на sqrt(d_k), чтобы значения перед softmax
не становились слишком большими."
```

Пример Middle:

```text
question_id = 42
grade = 2
reference_answer =
"При независимых компонентах query и key дисперсия их dot product
растёт пропорционально d_k. Деление на sqrt(d_k) нормализует масштаб
logits и предотвращает насыщение softmax."
```

## Связи

```text
questions
    |
    +-- question_grade_configs
    |
    +-- criteria
            |
            +-- criterion_grade_configs
                    |
                    +-- criterion_grade_anchors
```

---

## Итоговый score вопроса: `0..100`

Для каждого активного criterion сначала нормализуется его score:

```text
criterion_score = score / max_anchor_score
```

После этого применяется вес criterion для текущего грейда:

```text
question_score =
100 * SUM(weight * criterion_score) / SUM(weight)
```

В сумму входят только criteria, у которых существует `criterion_grade_config` для текущего грейда.

### Пример

Для Middle используются три criteria:

```text
Criterion A:
weight = 3
anchors = 0, 1
полученный score = 1

Criterion B:
weight = 2
anchors = 0, 1, 2, 3
полученный score = 2

Criterion C:
weight = 1
anchors = 0, 1, 2
полученный score = 1
```

Нормализованные значения:

```text
A = 1 / 1 = 1.0
B = 2 / 3 = 0.6667
C = 1 / 2 = 0.5
```

Итог:

```text
question_score =
100 * (
    3 * 1.0
  + 2 * 0.6667
  + 1 * 0.5
) / (3 + 2 + 1)

question_score ≈ 80.56
```

Если какой-то criterion для этого грейда не используется, строки в `criterion_grade_configs` для него нет, и он не входит ни в числитель, ни в знаменатель.

## Ограничения

1. `min_grade`, `grade` — только `1..3`.
2. `question_grade_configs.grade >= questions.min_grade`.
3. `criterion_grade_configs.grade >= questions.min_grade` соответствующего вопроса.
4. Для каждого `criterion_grade_config` есть anchor `0` и хотя бы один положительный anchor.
5. Для каждого грейда, на котором используется вопрос, существует `reference_answer`.
6. `weight > 0`.
7. `questions.code` — стабильный идентификатор вопроса.
8. При существенном изменении вопроса или rubric увеличивается `questions.version`.

## Конфигурация для Interviewer

Backend берёт:

- `question_text`;
- criteria, для которых существует `criterion_grade_config` текущего грейда.

Пример для Middle:

```json
{
  "question": "Зачем в attention делить скалярное произведение на sqrt(d_k)?",
  "criteria": [
    {
      "criterion_id": "scaling_operation",
      "description": "Понимает операцию масштабирования attention logits"
    },
    {
      "criterion_id": "scaling_reason",
      "description": "Понимает причину масштабирования attention logits"
    }
  ]
}
```

Сессионные поля backend добавляет отдельно:

```json
{
  "dialogue": [],
  "follow_up_count": 0,
  "max_follow_ups": 2
}
```

## Конфигурация для Evaluator

Backend берёт:

- `question_text`;
- `reference_answer` для текущего грейда;
- criteria для текущего грейда;
- anchors этих criteria для текущего грейда.

Пример:

```json
{
  "question": "Зачем в attention делить скалярное произведение на sqrt(d_k)?",
  "target_level": "middle",
  "reference_answer": "...",
  "criteria": [
    {
      "criterion_id": "scaling_operation",
      "description": "...",
      "anchors": [
        {"score": 0, "description": "..."},
        {"score": 1, "description": "..."}
      ]
    },
    {
      "criterion_id": "scaling_reason",
      "description": "...",
      "anchors": [
        {"score": 0, "description": "..."},
        {"score": 1, "description": "..."},
        {"score": 2, "description": "..."},
        {"score": 3, "description": "..."}
      ]
    }
  ]
}
```

`weight` evaluator не передаётся. Итоговый score `0..100` считает backend после получения оценок по criteria.

`dialogue` добавляется из состояния текущей тренировки.
